Domain experts

把一个大问题，拆成四种专业判断。

每个专家拥有自己的工具、上下文和权限，输出结构化结果，等待总师验收。

CASE / REQUIREMENTS

需求与工况

维护 caseDict，澄清目标、材料、边界条件与未决问题。

GEOMETRY / MESH

几何与网格

生成、校验并交付带命名区域的几何与网格产物。

SOLVER / RUN

求解执行

配置求解器，运行任务，诊断残差与失败原因。

POST / REPORT

后处理与报告

提取证据、生成图表与报告，回写可追踪的结论。

Designed for control

自由度留给专家，边界留给系统。

01

默认不自由对话

专家之间不形成不可审计的聊天群。需要协商时，由总师限轮次中转，并明确终止条件。

02

协议先于界面

CLI、TUI 和 VS Code 都消费同一套版本化事件，不解析模型自然语言，也不依赖内部类。

03

产物先于叙事

任务传递 ID、输入摘要和产物引用；几何、网格、日志与报告都能被复核和重放。

04

权限随工具声明

文件、Shell、求解器和网络操作都有范围、超时、可取消性与人工审批边界。

A staged blueprint

先把核心做稳，再把边界推远。

未来蓝图按可靠性与真实负载演进，每一步都复用同一套 Agent Core 与事件协议。

PHASE 01

Core + CLI

Supervisor、任务状态、事件协议、审批与可重放日志。

PHASE 02

TUI

任务树、实时日志、费用观测与交互式恢复。

PHASE 03

VS Code

工作区、diff 审查、终端与产物预览的编辑器体验。

PHASE 04

Remote workers

按时长、许可证与 GPU 资源需求引入队列和远程执行。

The Logos principle

不是让更多智能体说话，而是让工程结果更可信。

底层规划采用 Deep Agents + LangGraph 提供状态、工具和恢复能力；基础设施按真实任务需求逐步引入。Logos 的每一次扩展，都必须保留可观察、可审批、可复现的工程边界。
