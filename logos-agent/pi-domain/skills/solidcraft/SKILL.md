# SolidCraft
## 当前机器的软件位置

首次使用先读取运行时提供的软件清单；缺失或过期时调用 `software_discover`。使用返回的当前主机绝对路径，不要全盘搜索或把历史部署路径当作本机事实。安装、SDK、许可证和 MCP 连接分别验证；远程任务必须在目标主机探测。


## 工具选择与触发

只要任务需要使用 CAD 进行模型构型的重建，就调用本技能并使用 SolidCraft MCP。适用于零件、支架、机架、机械臂、整机装配的重建、改型及参数化建模。不要把导入的参考实体或网格直接称作完成了原生参数化重建。

服务名是 `solidcraft`，工具命名空间为 `mcp__solidcraft__*`。通过 Logos 的工具发现机制查找 `inspect_design`、`list_commands`、`execute`、`batch`、`measure`、`screenshot`、`open`、`save` 和 `export`，按实际返回的 schema 调用。优先 MCP 执行；需要可复现脚本时可使用已安装的 `solidcraft-cli`。

使用当前主机的软件发现结果和实际 MCP 配置。不要假定已有常驻会话或固定可写目录；产物保存在当前工作区，桌面桥接方式见 references/mcp.md。

大型 CAD 输入要先做导入风险判断。STEP/AP242 文件超过约 10 MB、包含超过 100,000 个实体、多个产品实例或大量曲面时，先记录文件大小、格式、产品/实体数量和单位，再单独调用 `open`，不要把导入和后续编辑放在同一个批次中。此类导入允许较长时间；MCP 连接的请求超时应使用 1800 秒配置。若 `open` 超时，先检查 SolidCraft MCP 进程和会话状态，等待或重新连接一次后再判断是否失败，禁止立即重复导入造成并发解析。若整个装配仍无法完成，按产品/零件拆分为多个输入逐一导入或请求用户提供分件文件，并保留原始 STEP 不变。

可用 `scripts/step_preflight.py <file.step>` 做只读预检查；它只统计文件和 STEP 实体，不修改输入。

## 编辑前读取和补充备注

编辑任何已有组件、零件或特征前，先读取设计属性、组件/特征名称、时间线定义、关键参数及其备注，结合 `inspect_design`、`document.metadata`、`parameters.list` 和必要的 `timeline.inspect` 判断它的用途、来源、接口和编辑意图。不能只根据实体外形或自动生成的名称猜测组件含义。

如果设计、组件或关键参数缺少能够说明用途的备注，且当前任务允许修改文件，应先补写备注再继续编辑：设计级信息使用 `document.metadata.set`（例如 `project`、`part_number`、`revision`、`description` 或反向 DNS 自定义键），参数说明使用 `set_parameter` 的 `comment` 或 `parameters.comment`。SolidCraft 当前没有通用的任意实体属性表时，用清晰的组件/特征名称、参数备注和设计元数据表达相同信息；不要覆盖已有备注，不确定的内容标为“待确认”，不要编造来源、尺寸或功能。

补写备注本身也是设计修改：先检查是否有未保存改动，必要时另存副本或建立检查点；完成备注后确认其已写入，再执行几何编辑并保存。

## 建模与交付要求

1. 先检查会话现有模型。确认单位、坐标系、参考尺寸和装配位置；区分用户给定尺寸、测量值和假设。已有设计先另存副本或建立检查点，避免丢弃未保存工作。
2. 在模型中表达可编辑的草图、特征和关键参数。参考导入、网格显示与原生重建分开记录；重复零件用组件实例表达。
3. 按阶段 batch 建模；检查返回的失败和回滚状态。超时或断线后先检查设计状态，不盲目重发修改。重复失败时缩小到最小操作，保留可恢复模型并说明阻碍。
4. 每个阶段用预期尺寸、包围盒、体积等独立数值检查；检查 timeline 的错误与警告。需要参数化时检查约束自由度和参数变更结果。布尔成功和正体积不能单独证明几何正确。
5. 装配检查轴孔配合、连接位置和干涉；要求运动时建立关节、固定基座和限位，验证实际位姿变化。没有建立运动约束的几何只能称为静态演示。
6. 保存 `.solidcraft`，按需求导出 STEP 等交换格式；重开检查并截图查看。报告原生重建范围、缺失件、验证结果及未验证项。没有载荷或净空验证时，不宣称可制造、满足承载或可飞行。

配套 checking 脚本的第三方依赖是可选项，仅在任务需要独立 STEP 对比时使用；日常建模通过已接入的 SolidCraft MCP 即可完成。
