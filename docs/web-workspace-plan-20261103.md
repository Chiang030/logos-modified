## 1. 已明确的需求

| 项目 | 第一版约定 |
|---|---|
| 用户规模 | 20 人以内 |
| 任务并发 | 全站最多 5 个运行中的任务；超出排队 |
| 访问方式 | 内网网页，桌面浏览器优先 |
| 界面 | 直接复用插件界面、品牌、聊天渲染与交互，可以调整网页布局 |
| 项目 | 必须先选择个人空间中的文件夹，再建立或打开项目 |
| 文件 | 每人独立目录，支持本机文件上传、目录浏览与文件查看 |
| 目录权限 | 用户只能访问自己的目录；不做共享文件夹、复杂角色授权或团队项目权限 |
| 登录 | 飞书企业身份登录；已有飞书组织，尚未创建应用 |
| 模型账号 | 管理员统一配置，普通用户选择管理员开放的模型 |
| 用量 | 后台按飞书登录账号统计，不依赖用户手填姓名 |
| 开发位置 | 在服务器上开发，保留现有 CLI 和插件的可用性 |

“没有复杂权限系统”不等于“所有用户能访问所有文件”。第一版只实现固定所有者规则：用户、个人目录、项目、会话、任务和文件请求必须匹配同一所有者。管理员具有系统配置和用量查看能力，不默认提供浏览所有用户文件的界面。

以下是实施建议，可在开发过程中调整，并非用户已经逐项确认的要求：每用户默认最多 1 个活动任务、同一项目串行写入、第一版文件预览为主不做手工代码编辑、采用 SQLite、前后端使用 TypeScript。

## 2. 已核实的复用边界

现有前端位于 logos-agent/vscode-extension/webview-ui/src。App.tsx 通过 acquireVsCodeApi().postMessage 与扩展通信。React 组件、样式、消息时间线、工具卡片、模型选择等可以直接复用，但浏览器不能原样执行这条 VS Code 通信链路。

现有后端不是独立 HTTP 服务：
- src/webviewBridge.ts 依赖 vscode，处理聊天、会话、文件链接和设置交互。
- src/localRuntime.ts 依赖 VS Code 配置、事件和存储设施，并负责 Pi 进程生命周期。
- src/rpcClient.ts 基本独立于 VS Code，可以复用 JSONL RPC、请求匹配和进程事件处理。
- src/sessionStore.ts 可以复用会话恢复与转录读取思路，网页项目和用户索引改为数据库。
- src/usageStore.ts 是本地 JSON 账本，身份可以手工选择；网页端改用登录身份与中心账本。
- Pi 已有普通回复、usage、压缩和摘要等用量记录。需要核实实际流式事件与转录覆盖，不能仅搬现有助手回复统计。

实施方式：保留聊天组件和 Pi 执行核心，抽出宿主适配层，新增 Web 服务、登录、个人空间、任务调度和用量数据库。避免复制两份长期维护的聊天 UI，也不把整个 vscode API 在服务端模拟一遍。

## 3. 用户操作流程

1. 打开内网入口，点击“使用飞书登录”。
2. 飞书完成授权，后台建立本地登录会话，以稳定的飞书身份映射内部 userId。
3. 首次登录自动创建个人空间；页面显示“我的项目”和“我的文件”。
4. 点击“打开文件夹”：只能选择个人空间内的文件夹，也可新建文件夹或上传本机资料。
5. 选择文件夹后点击“以此文件夹建立项目”，填写可修改的项目名称。
6. 系统关联项目与该目录，进入工作台。已有项目目录直接打开，不重复注册。
7. 新建对话、选择模型、提交任务；系统记录发起人的身份，排队或运行。
8. Agent 生成文件后，文件树自动更新；点击消息中的文件链接，在预览区打开。
9. 刷新、关闭或重新打开浏览器，可回到同一项目和会话查看进度及结果。
10. 后台持续记录用量；管理员在独立管理页查看各账号统计。

“打开文件夹”指服务器个人空间里的目录。本机文件或本机文件夹必须上传后进入服务器，网页不会把用户电脑路径直接当作服务器工作区。

## 4. 页面与布局

### 4.1 登录页和项目首页

登录页保留 LOGOS 品牌，只提供飞书登录入口和登录异常提示。项目首页展示当前用户自己的最近项目、任务状态、打开文件夹、新建目录、上传入口。

项目卡片显示名称、个人空间内的相对位置、最近访问时间和运行状态。默认不暴露服务器内部绝对路径。

### 4.2 工作台

| 区域 | 设计 |
|---|---|
| 顶栏 | LOGOS、当前项目、项目切换、任务状态、飞书头像与姓名 |
| 左栏 | “文件 / 会话”切换；文件树、会话历史、新会话入口 |
| 主区 | 原插件的聊天内容、工具执行卡片、输入框、模型与思考档位选择 |
| 右侧预览区 | 点击文件时展开，可调整宽度、收起和切换文件标签 |
| 设置入口 | 普通用户显示个人偏好和允许选择的模型；管理员另外进入系统设置 |

默认以聊天为主，预览区未打开时释放宽度。桌面宽屏采用左侧窄栏、聊天主区、可展开预览区；窄屏使用抽屉与标签切换，不强行压缩三列。

保留插件的消息样式、Markdown、代码块、流式输出、工具状态、停止按钮、错误提示、历史对话和模型切换交互。网页版用飞书头像和姓名替换手工姓名登记；不保留 VSIX 更新按钮；模型密钥配置移到管理员页面。上下文占用指示与后台累计用量是不同概念，前者可以继续显示。

软件发现改为“服务器可用软件”：普通用户查看可用性，管理员维护共享软件路径和刷新扫描，避免每个用户修改全局工具配置。

### 4.3 文件功能边界

第一版包含：
- 个人空间与项目内目录树，按需展开、刷新、面包屑、文件名搜索。
- 新建目录、上传单文件/多文件/文件夹、下载单文件。
- 上传进度、失败重试、同名文件明确选择保留两份或覆盖，不能静默覆盖。
- 文件大小、修改时间、类型与预览。
- 将文件以明确的项目相对路径引用到聊天。
- Agent 创建或修改文件后的通知与刷新。
- 会话中点击文件路径，跳到对应项目文件预览。

| 文件类型 | 首版显示方式 |
|---|---|
| 文本、代码、JSON/YAML、求解器输入文件 | 只读语法高亮、行号、搜索、复制 |
| Markdown | 安全渲染与源文切换 |
| 日志 | 有限窗口/分段加载，可刷新，避免整份巨型日志进入内存 |
| PNG/JPG/WebP 等图片 | 缩放、适配窗口 |
| PDF | 浏览器预览或下载回退 |
| CSV/TSV | 有行列上限的表格预览；不一次读取整个大文件 |
| STEP/STL/ODB/VTU 等工程或二进制文件 | 文件信息与下载；现有结果图片可直接预览，原生三维交互另立阶段 |

建议首版不提供通用在线终端、手工代码编辑、删除整个项目目录、任意压缩包自动解压和多人协同编辑。这些功能不影响“查看文件并让 Agent 工作”的主要闭环。将项目从列表移除或归档，不等于删除目录中的实际数据。

文件上传上限、文本预览上限和个人磁盘配额应可配置；先根据实际样例文件大小确定默认值，大型仿真数据不按聊天附件小文件标准处理。目录上传不保证保留空目录或本机特殊权限，界面须说明实际上传内容。

## 5. 个人空间与项目模型

建议将数据放在代码仓库外，使用配置项 LOGOS_WEB_DATA_DIR。示意结构：

    <data-root>/
      users/<internal-user-id>/workspace/
        wing-study/
        heat-transfer/
      state/
        application.sqlite
        sessions/<user-id>/<project-id>/<session-id>/
      uploads/
      logs/
      backups/

实际落盘位置在环境验证阶段确定。目录名使用内部稳定 ID，不使用可重名或可改名的飞书显示名称。

层级关系：一个用户有一个个人空间；一个个人空间包含多个项目目录；一个项目包含多个会话；一次用户提交形成一个任务；一次任务可能包含多个模型请求和多个工具操作。

项目记录保存 ownerId、名称、个人空间内相对路径、创建时间和最近使用时间。相同用户的同一规范化目录只能注册一次。第一版建议不允许相互重叠的项目根目录，以免父子项目同时写入绕过项目锁；用户可在项目内建立普通子文件夹。

### 固定所有者规则

所有文件接口、下载、图片预览、会话读取、任务控制、事件订阅都从服务端登录态取得用户身份。客户端只传项目 ID、会话 ID、相对路径，不通过提交 userId 来指定身份。

目录访问要处理 ../、绝对路径、符号链接、上传路径和重命名竞态。对不存在的新文件，校验其已存在父目录；读写时采用受约束的文件操作，不能只检查字符串前缀。第一版不允许符号链接跳出个人空间。

同样的规则必须覆盖 Agent 的 read/write/bash、Python 脚本和仿真工具。不同用户各有进程、HOME、配置、缓存与临时目录，不能共用登录凭据或可写的会话目录。工作目录 cwd 本身不是文件隔离。

初步实施方向是受约束的 Linux 执行环境，仅挂载当前用户目录、必要的只读工具链及当前任务资源。是否使用 bubblewrap、独立 Linux 身份或容器，在 P0 通过现有求解器兼容性测试后定。不会为了简化开发而使用共同的、不受约束的宿主进程代替已承诺的目录隔离。

既有仿真服务或 MCP 服务如果能代为读取宿主文件，也必须受同一目录边界约束；需要在 P0 验证，不能只隔离外层 shell。

## 6. 飞书登录

采用企业自建应用的网页 OAuth 授权流程。首版只接入本企业用户，不建立额外账号密码体系。

登录流程：Web 后端发起授权并绑定 state → 用户在飞书授权 → 浏览器回到配置的回调地址 → 后端使用授权码获取用户身份 → 校验企业归属和应用可用范围 → 建立本地登录会话。

- 内部 userId 与飞书企业/应用范围内的稳定用户标识绑定；姓名、头像只做展示。
- 使用服务端会话及 HttpOnly Cookie，部署 HTTPS 时启用 Secure，设置合适的 SameSite 和过期策略。
- 校验 OAuth state、回调地址和一次性授权码；PKCE 是否启用以选用的飞书流程实际支持为准。
- 飞书 App Secret、授权交换结果和模型 API Key 不返回给浏览器，不写入前端构建文件。
- 普通用户不能通过手工切换姓名改变用量归属。
- 管理员账号通过明确配置的飞书身份指定，不能把第一个登录的人自动升级成管理员。
- 登出结束 Web 会话；已经接受的后台任务继续执行，重新登录后可查看。禁用用户的处理策略在部署前确定。

需要公司管理员完成或协助：
1. 在飞书开放平台创建企业自建应用。
2. 开通所选网页登录流程需要的能力与最小身份读取权限。
3. 配置可访问员工范围、应用版本发布与企业审批。
4. 配置实际内网入口和精确回调地址。
5. 将 App ID、App Secret 通过服务器配置或密钥管理方式交付，不要求在聊天中粘贴密钥。
6. 提供至少两个测试账号，用于验证身份分离和文件隔离。

内网部署不自动意味着必须把网页公开到互联网。OAuth 回调通常由用户浏览器完成，浏览器须能访问内网入口，服务器须能访问飞书接口。内网 DNS、HTTPS 证书信任及飞书后台对回调地址的校验要求，需要用实际应用做一次完整验证；目前未确认可用域名。若用户从手机内打开应用，也要验证手机的内网连通性。

飞书具体接口路径、权限名称和应用配置以实施时开放平台当前文档与实际后台为准，本计划不把未经核实的接口路径作为实现依据。

## 7. 管理员统一模型配置与用量后台

管理员配置提供商、API 地址、API Key、协议、允许使用的模型和默认模型。普通用户选择开放模型，不能读取密钥或改写全站配置。运行中的任务固定使用开始时的配置版本，管理员修改配置不应让已运行任务中途串换账号。

用户飞书身份和模型提供商账号是两套身份。每个模型调用必须关联 actorUserId、projectId、sessionId、runId、modelRequestId、provider、model、模型连接 ID、发生时间和状态。

### 统计口径

记录输入 tokens、输出 tokens、缓存读取、缓存写入、总量、已知/未知用量状态。保留提供商原始 usage 与规范化结果，明确缓存与 reasoning 是否已包含在其他字段中，不能重复相加。

计量范围包括普通回复、工具调用前后的模型回复、上下文压缩、摘要、分支总结以及可观测的子任务模型调用。后台调用继承发起任务的用户身份。网页断线、刷新、切换项目或重新登录不改变任务归属。

优先在模型调用完成的位置或具有完整 usage 的运行时事件收集，并以持久化转录中的 usage、compaction、branch_summary 等条目补账。不能直接把会话累计数和逐条事件相加；同一个上游调用只能入账一次。重试是真实的另一请求时分别记录；重复事件与断线重放不能再次记账。

失败、中止或断流仍可能产生消耗：有上游 usage 就计入，没有则标记“用量未知/待核对”，不能推断为零。提供商未返回数据时，不承诺与官方账单完全一致。第一版统计真实可观测 tokens，金额估算和自动对账可以后续加入。

### 管理页

- 按飞书用户、日期范围、提供商、模型筛选。
- 展示调用数、失败数、输入/输出/缓存 tokens、已知总量、未知用量次数。
- 按用户汇总，并可下钻到项目、任务和请求记录。
- CSV 导出，导出时处理表格公式注入。
- 数据按 UTC 存储，按 Asia/Shanghai 展示日/月统计边界。
- 第一版不做充值、付费套餐、按人扣费或硬性 token 配额。
- 普通聊天界面不增加其他用户用量排行榜；管理员用量页与普通工作台分开。

既有 CLI/插件产生的历史使用记录，不按姓名自动映射到飞书账号；首版中心账本从网页使用开始记录。未来若需要统一 CLI/插件统计，需额外接入同一认证和计量服务。

## 8. 并发、队列和任务生命周期

全站上限 5 个运行任务，建议每用户默认最多 1 个，同时同一项目只允许 1 个写入任务。其余任务按用户公平排队，并显示排队状态，避免某个用户一次提交大量任务占满队列。管理员可调整每用户并发，不将这个建议写死。

“任务”定义为一次用户发送触发的 Agent 执行轮次及其受管理的工具/计算子进程，不是一个浏览器标签、聊天会话或单次模型请求。任务产生的长计算未结束时，不能仅因为浏览器断开或模型回复完成就提前释放相关计算配额。求解器线程数、显存和许可证还需独立约束，5 个任务不代表每个任务都可占满整台机器。

状态至少包括 queued、starting、running、cancelling、completed、failed、cancelled、interrupted。取消时处理任务进程组或受管理的计算作业，等待确认停止后释放资源；排队任务可直接取消。

浏览器与运行进程解耦：
- 刷新和断网只中断事件订阅，不结束任务。
- 任务状态和事件序号持久化，重连先取得快照再补发缺失事件。
- 发送请求带幂等 ID，重试不会启动重复任务。
- 同一会话只允许一轮执行写入；多标签页提交进行冲突提示或排队。
- 切换项目不会改变已启动任务的工作目录和所有者。
- Web 接口服务重启后可重连独立运行管理器。
- 运行管理器或整机重启不承诺恢复原执行进度：先核对实际进程，将失去进程的任务标记 interrupted，保留产物，不自动重跑有副作用的任务。

## 9. 技术方案与目录安排

### 技术选择

| 部分 | 建议 |
|---|---|
| 前端 | 复用现有 React/TypeScript/Tailwind 组件，新增浏览器入口和布局 |
| 前端通信 | HostBridge 接口；插件适配 postMessage，Web 适配 HTTP + WebSocket |
| 后端 | Node.js/TypeScript；轻量 HTTP 框架，具体库在 P0 确认维护情况与已有依赖后选择 |
| 流式输出 | WebSocket，统一用户会话、事件序号、心跳和断线重连 |
| 持久化 | 单服务器 SQLite WAL，短事务、唯一键去重、版本迁移与一致性备份 |
| 大文件与转录 | 文件系统保存；数据库存元信息、索引、任务和用量记录 |
| 执行 | 复用 Pi CLI/RPC，独立运行管理器、队列与个人执行环境 |
| 部署 | 内网反向代理和 HTTPS，服务由 systemd 等进程管理器托管 |

20 人、5 个并发任务的初期规模不需要先引入 Redis、Kubernetes 或多节点数据库。SQLite 数据库放本地磁盘，不放网络文件系统。WAL 模式备份使用数据库备份机制，不能仅拷贝一个正在写入的 .sqlite 文件。

建议新增 logos-agent/web/，内部划分 server、ui、worker 与测试；公共协议、UI 和运行时模块按实际依赖关系逐步抽到 logos-agent/shared/。先把 App 的 acquireVsCodeApi 依赖改为注入的宿主接口，再从共享入口供插件和网页使用。现有命令、包版本、插件构建与测试应持续可用。

建议数据库实体：users、auth_sessions、projects、conversations、runs、run_events、model_connections、model_requests、usage_entries、schema_migrations。是否单独建立文件索引表按文件搜索规模决定，第一版可按需读取目录。

核心接口分组：登录/退出/当前用户、个人目录与项目、文件列表/上传/预览/下载、会话与消息、任务与取消、实时事件、管理员模型配置和用量查询。所有查询都进行固定 ownerId 校验；管理员接口额外校验管理员身份。

## 12. 第一版完成定义

- 使用真实飞书账号登录，不能伪造另一个用户的身份提交任务或用量。
- 用户先打开自己的文件夹，再建立项目和开始聊天。
- 用户 A 在文件接口、下载、事件订阅以及 Agent 工具中都不能访问用户 B 的文件和会话。
- 网页消息显示、模型选择、工具执行与停止交互延续插件体验。
- 上传的资料和 Agent 生成的结果可以在文件树与预览区找到。
- 5 个并发上限和排队机制有效，同项目写入不互相覆盖。
- 页面刷新后能恢复任务显示，不重复发送、不重复收费统计。
- 管理员能够按飞书账号查询 tokens，并看到未知或缺失计量。
- 更新服务后，项目文件、历史会话、用量和用户身份仍然存在。
- 既有 CLI 与插件的核心回归测试通过。

需要的验证分为：协议与计量单元测试、真实数据库/文件/任务管理集成测试、浏览器端登录与项目完整流程、真实飞书联调、代表性求解器运行和 5 任务并发演练。模型故障与重试优先用本地可控测试服务验证，外部真实请求只做必要联调。
